# ADR 010 — Educational storage extensions

Status: implemented locally; independent review and AWS deployment remain unverified.

Retained Deleted image tombstones retry deletion of their exact key hourly during active sessions. This repairs late remote PUT effects after earlier cleanup without a bucket scan or metadata resurrection; pausing defers the repair until the next session.

Projection publication has an independent destination-filtered Outbox drain in the same Reservations host. The original business drain excludes that destination, so an unavailable/misconfigured projection queue cannot monopolize the oldest pending row and block payment/inventory commands. Both still use the same owned PostgreSQL Outbox transaction and lease implementation; no extra Fargate service or shared domain entity is introduced.

EXT-001 and EXT-002 deliberately extend the original no-image/four-queue baseline. S3 holds image bytes while Catalog PostgreSQL owns image metadata. DynamoDB holds a Reservations-owned read projection; PostgreSQL remains the booking authority. Five hosts remain unchanged. No event sourcing, generic repository, cross-schema join, second upload path or service host is added.

The latest extension request explicitly requires no ALB/no NAT. Existing ALB teaching work is retained as `enable_alb_study_profile`, default false. Direct Gateway TLS and one Gateway session task are the extension default; the earlier ALB/two-replica profile remains an opt-in artifact with its own cost/TLS/circuit verification obligations. No deployed state/resources were changed. Earlier review reports are preserved and do not review these extensions.

For images, bounded raw PUT through Blazor InputFile avoids multipart/browser JavaScript/CORS. StbImageSharp2.30.16 is a .NET-compatible MIT/public-domain image decoder without commercial-license activation. Signature checks, PNG structure/CRC checks, full decoding and 2048×2048 bounds precede storage. JPEG decoding is bounded but not a malware scanner. EXIF/metadata are not stripped; images are served only as detected JPEG/PNG with a private object capability. No arbitrary documents/SVG. Two uploads per process bound CPU/memory; temporary disk spooling bounds bytes instead of unrestricted buffering/base64 storage.

PostgreSQL and S3 cannot share a transaction. The owned intent commits before PUT; matching HEAD metadata repairs the PUT-success/metadata-failure boundary. A two-minute work lease exceeds the40second upload budget and25second reconciliation budget. Deletion supersedes Pending/Ready, waits for an active lease, and retries exact-key deletion. Ready updates are fenced by owner/status/lease. Deleted tombstones prevent an old upload intention being reused. S3 timeouts can represent unknown outcomes; reconciliation handles them without asserting failure means no object exists. Absolute guarantees against unbounded remote execution require a stronger object-version/finalization protocol; that remains an AWS verification/evolution topic.

Reservations persists the tour name in the quote and accepted booking. Existing data cannot reconstruct the historical name: migrations use the explicit legacy-unknown marker. Reservation.Version already increases through Saga Record; the owned context's async SaveChanges also increments otherwise modified reservations and adds a snapshot Outbox record before the same local commit. Direct production SQL updates of reservation card fields would bypass this seam and must explicitly emit/increment or be prohibited. Current production paths use tracked entities. Rebuild uses only Reservations' rows.

DynamoDB's main item is keyed by authenticated owner/reservation; a UserBookings GSI gives newest-first keyset pages. The GSI is eventually consistent; the main detail read is consistent. A dedicated32byte AES-GCM cursor key binds identity, query, expiry and last key; no extra cursor SQL table/shared Gateway keys are needed. The projection has its own queue and DLQ. Its consumer uses atomic version conditions instead of a PostgreSQL Inbox before the external write. ACK follows successful Put or a verified stale no-op; redelivery after an uncertain boundary is expected.

S3Proxy filesystem storage and DynamoDB Local are disposable-development dependencies with preserved named volumes and loopback ports. They do not simulate AWS IAM, public-access policy enforcement, regional availability, throttling/billing or GSI propagation faithfully. Fake local credentials are only configured with explicit emulator endpoints; cloud clients use task-role credentials. DynamoDB Local requires alphanumeric fake access IDs and a writable UID1000 data directory; a one-shot initializer sets only that directory's owner. Application containers remain non-root.

Both data stores survive session Stop. S3 force_destroy=false and DynamoDB deletion protection plus prevent_destroy make whole-stack destruction intentionally fail until a separately reviewed data-retention/deletion decision is made. Never remove these guards just to make tests pass: offline Terraform tests now use mocked plan-time values, avoiding protected-resource teardown. No broad bucket purge, live table deletion, Inbox reset, AWS provisioning or paid service activation was performed.
