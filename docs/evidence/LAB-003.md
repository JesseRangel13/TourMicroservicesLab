## Delivered behavior

Reservations owns Reservations, Sagas, IdempotencyRequests, History, Inbox, Outbox and an
informational TourProjections table. Checked-in migration `20261003221450_InitialReservations`
and Catalog's additive `20261003221442_MessagingLeasesAndInbox` were generated and applied by
the isolated migrator roles. Existing Identity/Catalog seed and Outbox data were preserved.
The provisioner initializes the four input queues and their DLQs using the actual AWS SQS SDK.
Package AWSSDK.SQS 4.0.100.15 is pinned and all affected lockfiles are updated.

An authenticated request supplies accepted price/quantity and a required idempotency key; ownership
comes from the validated token. A stable intention requests an immutable quote using Reservations'
dedicated service signing key. HTTP executes before the local transaction with a three-second
timeout, ten-call concurrency limit and cancellation. The atomic commit includes Reservation,
Saga AwaitingAvailability, original 202/Location, history and HoldSeats Outbox intent. A uniqueness
loser rolls back its failed PostgreSQL transaction before rereading the committed winner.

The live workflow uses real queues: HoldSeats → Catalog Inbox/inventory/result → Reservations
Inbox/state/history → AwaitingPayment plus stable ProcessPayment, or Failed with no payment work.
Payments/Notifications consumers are disabled; queued work is not acknowledged by unfinished
stubs. There is no confirmed reservation, payment provider, email sender or cancellation endpoint.

Outbox SQL atomically claims pending deliveries with SKIP LOCKED and recoverable ownership leases.
SendMessage executes after the claim transaction/connection ends; marking publication checks the
current unexpired owner. Retries preserve message/delivery identities. Inbox deduplication includes
a canonical content fingerprint; Inbox, business effects and outgoing intents commit together.
DeleteMessage follows commit/deduplication; observed visibility renewal, bounded processing,
long polling and async worker scopes preserve cancellation/lifetime boundaries.
Malformed/unsupported messages remain unacknowledged and broker redrive is bounded to five receives.
Delivery is at least once; there is no exactly-once network delivery claim.

Blazor adds accepted-price/quantity submission, own/admin-filtered list, detail and timeline using
per-user clients through Gateway. An uncertain retry preserves the same component intention/key;
deliberate reset generates a new key. Active nonterminal detail polls every three seconds and joins
its cancellable polling task on disposal. No circuit retains a DbContext or shared authorization header.

## Findings and limits

Existing Catalog handlers needed to join the Inbox-owned transaction rather than independently
commit. This prerequisite adaptation is tested by rollback; it is not a defect attributed to the
independently reviewed LAB-002 behavior. See `docs/decisions/003-durable-reservations.md`.

Unsupported confirmation/release/expiration results remain unacknowledged and can reach DLQ.
Catalog expiration runs, but Reservations deadline/compensation processing is deferred: a held
reservation can remain AwaitingPayment after expiration. Old retained test intents with nonexistent
Sagas are quarantined. Pending queues have finite retention; producer Outbox evidence is retained,
but an indefinite retention/replay guarantee is not implemented. Deduplication rows are not purged.

Automated browser automation remains NOT VERIFIED due to the Windows sandbox ACL initialization
limitation (`windows sandbox failed: helper_unknown_error: apply deny-read ACLs`). However, manual operator
testing in the browser was performed and confirmed: Alice reservation creation and transition to AwaitingPayment,
idempotency key protection and deliberate new intention reset, Bob 404 access denial on Alice's reservation,
and competitive final-seat booking where Alice obtained the seat (AwaitingPayment) and Bob was rejected with Failed InsufficientSeats.
Automated multi-user circuit isolation (AC-26) remains scheduled for LAB-007.
