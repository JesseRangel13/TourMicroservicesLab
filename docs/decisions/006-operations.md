# LAB-006 operational decisions

The LAB-005 independent review is PASS; no blocking prerequisite defect was found.

Polly's current breaker uses a sampled failure ratio ([official documentation](https://www.pollydocs.org/strategies/circuit-breaker)). That does not implement the required five consecutive failures. We retain the contract using a concrete, thread-safe `QuoteConcurrencyLimit` state machine and .NET 10's HttpClientFactory, SemaphoreSlim, TimeProvider and linked cancellation sources. No standard resilience handler is stacked over it. The counter counts failed logical quote operations after their bounded retries, in completion order, per Reservations instance. Any non-transient HTTP response resets the consecutive failure count. Caller cancellation neither increments nor resets it. After 30 seconds exactly one probe operation is admitted; its failure opens another 30-second window. A generation fence prevents already running pre-open operations from closing a newer circuit. Ten slots cover the entire operation, including retry delays; excess requests fail immediately. Attempt timeout is three seconds, total timeout defaults to ten seconds and covers reading the response and jitter delays.

Pauses consume one persisted occurrence per worker check, delaying that worker by one second without receiving/claiming work. Reset takes effect at the next check; already in-flight work can finish. QuoteTimeout consumes one occurrence per HTTP attempt and delays four seconds cancellably before quote creation. Payment acceptance consumes only provider modes; a PauseConsumption configuration cannot change an accepted operation's snapshot.

Regression found a caller-budget collision: the old test client and Gateway's per-user HTTP client timed out after ten seconds, including their own TLS setup, before a ten-second quote operation could return 503. The outage test caller now allows twenty seconds; Gateway allows forty to accommodate a configured quote budget up to thirty. Operational screens keep their shorter explicit cancellable budgets. This changes no Catalog attempt/total deadline and adds no retry.

DLQ inspection receives at most ten messages with 120-second visibility and stores the original body/receipt in a service-owned infrastructure table. Only redacted identifiers and an expiry leave the service. The receipt is never a browser capability. Replay atomically claims the inspection, validates its lease and original route, sends the identical body, then deletes from the DLQ. An uncertain send or delete failure leaves a retryable inspection and audit result; duplicates retain the original MessageId. Malformed envelopes can be inspected but cannot be edited or replayed through this API. Correct the consumer/configuration for valid poison envelopes; incompatible message contracts need an explicit migration decision, not arbitrary payload editing. AWS stale-receipt deletion can report success without removal, so a successful API result cannot promise absence of future duplicate delivery.

Operational storage uses per-service SQL migrations and runtime roles, like the existing Outbox plumbing. It contains no shared EF entities or domain rules. Snapshot metrics query only the owning schema, on an explicit diagnostics request, with a five-second statement timeout. No background database metric scraper is added. The optional collector does not affect base operation or provision AWS resources.
