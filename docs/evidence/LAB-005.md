## Implemented transition rules

| Trigger | Decision and completion guard |
|---|---|
| Availability deadline / late initial Held | Compensating + release original HoldId; no payment; Failed only after release |
| Valid Held | AwaitingPayment + fixed payment ID; deadline min(two minutes, hold validity) |
| Timely known charge with available hold | AwaitingConfirmation + ConfirmSeats; only actual timely confirmation becomes Confirmed |
| Payment deadline / unresolved hold expiration | PaymentUncertain + release + original-ID reconciliation; recovery deadline → ManualReview |
| Definitive decline/NotCharged | Compensating; Failed only after release; never invent no-charge from Unknown |
| Confirmation rejection/deadline or late charge | Refund + release; Compensating until both results; late charge never confirms abandoned seats |
| Confirmed cancellation before departure | CancellationPending + one full refund/release; either result order → Cancelled only when both complete |
| Exhausted refund / compensation deadline | ManualReview with pending flags; Admin retry preserves IDs and completed flags |
| Late confirmed / compatible duplicate | Preserve abandonment/compensation, ensure release; audited compatible stale result, no resurrection |
| Late charge after earlier Failed | Reopen Compensating, refund, retain prior failure-notice key; no duplicate notice at completion |
| Contradictory operation/reference/content | Poison exception; transaction rolls back and transport does not ACK; existing DLQ policy applies |
