# ADR 008: Controlled ALB Evaluation & Study Profile on Fargate

Status: implemented as reviewable artifacts; deployment and independent review pending.

The authoritative `specs/06-aws-and-costs.md` profile establishes cost-bounded study on AWS. To enable hands-on study of Application Load Balancer (ALB) concepts—including multi-AZ routing, target group health checking, zero-downtime rolling updates, and multi-replica load balancing—an internet-facing ALB is introduced specifically in front of the Gateway service across two Availability Zones (`us-east-1a` and `us-east-1b`). Business microservices (`catalog`, `reservations`, `payments`, `notifications`) remain internal single-task services discovered via private Cloud Map, preserving internal cost efficiency and the zero-NAT architectural baseline. No NAT Gateway, RDS/Aurora, customer-managed KMS key, or service-discovery sidecar is introduced.

Gateway ingress through the ALB is strictly restricted to `client_cidr` on HTTP port 80 (and direct TLS 8443). The ALB forwards to Gateway tasks over HTTPS port 8443 with Target Group stickiness (`type = lb_cookie`) enabled to preserve stateful Blazor Interactive Server SignalR circuits across two active Gateway task replicas. Internal APIs accept only Gateway's security group (and Catalog additionally accepts Reservations). Each API still validates JWTs, roles and ownership. Cloud Map A records discover private addresses for internal microservices, while the ALB provides a stable HTTP/HTTPS endpoint for the user-facing Gateway. HttpClient connections recycle every two minutes. This ALB configuration is time-bounded for active study sessions (~$0.54/day) and designed for complete clean-up via `terraform destroy`.

Initial sizes are 0.5 vCPU / 1 GiB per service, with desired_count zero. The smallest 0.25 / 0.5 profile in the specification is an estimate, not demonstrated capacity. Local capped-container evidence is in LAB-008.md; it does not establish AWS performance. Terraform rejects smaller sizes until a separate measured decision changes the bound. A cloud YARP ActivityTimeout of 40 seconds leaves room for the existing ten-second quote budget and transport overhead. Local proxy configuration is unchanged; the previously recorded 10/10 timeout boundary is an unrelated local defect.

SSM Standard SecureString carries separate PEM certificates and keys, each <=4096 UTF-8 bytes. Large PFX files cannot fit reliably. `RuntimeSecretFiles` materializes optional injected values into ephemeral Linux files owned by UID1654: directory0700, files0600. The CA private key is never injected. A combined OS/public-root and lab-CA trust file keeps both Neon/AWS and internal TLS verified. Npgsql uses VerifyFull; cloud configuration explicitly allows OS root trust. Local configuration retains its explicit CA path and PFX behavior. No validation bypass is introduced.

Execution roles pull only their images, write only their log streams and read only their parameter bundle. The ECR authorization-token API requires Resource `*`; it is the documented exception. Application roles access their owned input/DLQ and authorized send destinations. Gateway gets only Identity credentials and no SQS policy. The default AWS-managed SSM key requires no custom key or administrative KMS policy; changing to a customer key requires a separately reviewed key policy and scoped decrypt grant.

Privileged schema bootstrap/migrations run once from the operator PC using direct Neon connections. Runtime roles use bounded pools and may use Neon's pooler. Applications do not perform privileged migrations at startup. Provider-specific role capabilities and real cross-schema denials remain deployment gates. No business rule or Saga transition changes.

Private local state contains infrastructure metadata and references, never supplied secret values. Desired-count drift is ignored so Terraform will not unexpectedly start a paused session or pause an active one. Start/stop are deliberate operator actions. Stop preserves queues/database; destroy removes owned infrastructure and queues only after separate consent and review, retaining external Neon and separately managed parameters.
