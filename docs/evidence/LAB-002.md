## Implementation

Catalog owns Tour, TourSession, immutable Quote, SeatHold and a minimal durable Outbox. The checked-in
InitialCatalog migration creates indexes, referential/check constraints, unique request/quote/effect
keys, and concurrency versions. Runtime remains DML-only in catalog; catalog_migrator runs DDL in
the one-shot provisioner. Identity is unchanged and seeding preserves existing records/passwords.
Sample tours have future sessions on first seed; reruns never shift existing dates or reset edits.

Authenticated APIs provide paginated search/detail/sessions and all LAB-002 Admin operations.
Service-only quotes enforce five-minute validity, accepted MXN price, participants 1–6, checked long
arithmetic, immutable agreed amounts, and matching-request replay. Different input conflicts.
Dedicated RS256 service tokens require Reservations subject/permission/audience/issuer and at most
two minutes of validity. No public service-token endpoint exists. Gateway blocks internal routes.

Inventory handlers use cross-process PostgreSQL locks and conditional seat deduction. They persist
duplicate outcomes, release-before-hold tombstones, confirmation/expiration decisions, and Outbox
intents transactionally. No inventory HTTP endpoints, queue consumer, dispatcher, or timer worker
exists in LAB-002. Expiration is directly invoked in tests. Outbox publication timestamps stay null.

Interactive Server pages support tour search/pagination/details and Admin create/edit/activate,
session creation, price and capacity. Typed clients call Gateway routes with a fresh request bearer
header derived from the circuit principal. They retain no business DbContext or HttpContext.
Route changes dispose prior page instances and cancel requests. No automatic mutation retry occurs.

Decisions and resolved specification ambiguities: `docs/adr/002-catalog-transactions.md`.
Execution, migration commands, publication table and manual UI checks: `docs/catalog-execution.md`.

## Corrections and limits

The first HTTP test exposed a LAB-001 ProblemDetails customizer overwriting an explicit business
code with HttpError. It now supplies a fallback only when no code is present. The VersionConflict
HTTP test verifies the fix. A test helper's repeated RSA signing used IdentityModel's cached signer
after its short-lived RSA instance was disposed; local test signing disables signer caching. Host
issuers/verifiers retain DI-owned keys for their service lifetime.
The first extended restart run failed in its Catalog snapshot probe because the test process
survived PostgreSQL shutdown with a pre-restart pooled socket. The probe now disables pooling to
open a fresh physical connection after restart, just as the restarted hosts have fresh pools. The
rerun passed; no data was deleted and no general retry behavior was hidden inside the test.

Automated browser automation remains NOT VERIFIED due to the local Windows sandbox ACL initialization
limitation (`windows sandbox failed: helper_unknown_error: apply deny-read ACLs`). However, manual operator
testing in the browser was performed and confirmed: Tourist search/detail browsing, access restriction on
`/admin/catalog`, Admin tour/session creation, price/capacity editing, inactive tour visibility filtering,
and optimistic concurrency VersionConflict detection. Automated multi-user circuit isolation (AC-26) remains
scheduled for LAB-007.

AC-04 and AC-17 are verified at the Catalog handler/API layer only. No two-user reservation Saga,
payment prevention/delivery, refund or notification workflow exists yet, so those full acceptance
criteria remain partial. AC-07..09 Outbox/Inbox crash/replay behavior and AC-18 projection consumption
remain unimplemented. No exactly-once delivery or successful message publication is claimed.
