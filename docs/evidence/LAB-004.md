## Delivered implementation

- Payments-owned Operations, independently committed ProviderEffects, Inbox, Outbox, bounded Faults
  and Audit. Stable operation IDs, validated positive integer MXN amounts/owners, unique identities,
  contradiction rejection and optimistic versions protect repeated business operations.
- IPaymentProvider with durable simulated Success, Decline and TimeoutAfterCharge. Effects use a
  separate factory-created context/transaction before application results. A unique operation/hash
  identifies an effect; no random outcomes or authoritative in-memory collections are used.
- Consumption accepts Pending work with Inbox and commits before SQS ACK. Scoped processors claim
  recoverable sixty-second SQL leases using SKIP LOCKED, query/call the provider outside the application
  transaction, then fence and atomically record outcome/Outbox. Pending recovery queries the original
  ID before charging; Unknown recovery only queries, never starts another charge. A bounded worker
  call uses a forty-second cancellation limit. A timeout records Unknown, not Declined.
- Reservations consumes provider outcomes, requests ConfirmSeats and waits for actual Catalog
  SeatsConfirmed before Confirmed/ReservationConfirmed. Decline persists Compensating/ReleaseSeats,
  then Failed/ReservationFailed only after SeatsReleased. Saga row locks, related IDs, versions,
  Inbox and outgoing intent uniqueness protect compatible duplicates; history audits no-ops.
- Notifications accepts Pending terminal notices before ACK. Business uniqueness ReservationId/Kind
  complements message deduplication. Independent sender receipts use stable notification identity and
  SourceEventId/Kind; FailureThenSuccess durably fails twice. Sent follows a confirmed fictional receipt.
  Receipt-before-result crash recovery does not create another delivery.
- Owned query/detail endpoints, Admin reconciliation and bounded audited Admin fault selection/reset.
  Other tourists receive filtered lists/404; backend Admin authorization is explicit. Fault controls
  require LabFeaturesEnabled and per-validated-user rate limits. No endpoint publishes arbitrary
  success messages or forces a Saga state. Local config enables the two simulated lab controls only.
- Blazor payment/notification list/filter/detail, Unknown/provider outcome, reconciliation, simulated
  mode control, active cancellable detail polling and reservation links/progress. Per-request JWTs
  derive from the existing circuit principal; no shared authorization header, DB or SQS access from UI.
